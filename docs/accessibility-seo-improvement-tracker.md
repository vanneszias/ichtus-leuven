## Baseline

The 2026-08-30 audit covered source, rendered Dutch and English pages, desktop and mobile keyboard behavior, axe WCAG checks, metadata output, image delivery and development Core Web Vitals. The baseline score was 13/20: accessibility 2/4, performance 2/4, responsive design 3/4, theming 2/4 and implementation integrity 4/4.

A second pass on 2026-08-30 re-verified every item against the source, fixed the remaining gaps, and reviewed Lighthouse reports for `/nl` and `/nl/over-ons` (dev server, mobile emulation: accessibility 1.0 and best practices 1.0 on both pages; performance and SEO scores were dominated by development-only artifacts — unminified bundles, compile-time TTFB and the intentional non-production `noindex`).

Verification levels used below: items whose stated verification is a unit/config/render-level test were re-run locally and marked `DONE`; items whose stated verification needs the browser/e2e stack (Playwright + local Cloudflare/D1) are marked `VERIFY` because that stack cannot run in the sandbox used for this pass.

## Architectural constraints

- The site keeps its SPA navigation model: no `loading.tsx`, no full-page loading states, no full-DOM replacement on navigation. Loading feedback stays localized to the components that genuinely need it (registration and cancellation forms).
- Editorial accent classes (`accent-text-*`) intentionally have no color effect; heading colors are locked to contrast-safe pairs in `styles.css`. Do not reintroduce CMS-driven heading colors without a contrast-checked mapping.
- Content Security Policy still allows `unsafe-inline` scripts/styles (Next.js constraint). Hardening with nonces is a possible future improvement, tracked outside this document.
